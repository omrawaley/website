## Tiny Tapeout

Typically, manufacturing ASICS (and really any kind of semiconductor chip) can cost hundreds of thousands of dollars.

<img src="/images/tt02_board_top.jpeg"></img>

[Tiny Tapeout](https://tinytapeout.com) is an educational project that gives hobbyist developers access to this art by pooling together hundreds of peoples' money to get all of their designs on one unified chip. So, the manufacturing cost is split amongst everyone, each person paying their small share.

## Hack Club ASIC

I found out about this platform through Hack Club's new [ASIC](https://asic.hackclub.com) program, which aims to create a Tiny Tapeout chip designed entirely by teens.

And thus began my descent into the realm of RTL design.

## Beginning and Limitations

Before I started my design, or thought about what I wanted to make, I first had to research the restrictions.

A 1x1 Tiny Tapeout tile on the HC design can fit roughly 1000 logic gates.

For context, if you use the tile entirely as memory, you can only fit ~320 D flip-flops, or ~40 bytes of memory.

Yikes! Not a lot to work with.

However, despite that, I had seen many incredible projects like Rick Astley's _Never Going to Give You Up_ music video (by bitluni), an audio decoder and player, and even a tiny 8-bit RISC-V CPU.

These amazing projects almost seemed to defy all limits, which gave me hope that the platform was more capable than the specifications made it seem.

## Verilog and HDLs

Before starting a project, I digged into the technologies used to design an ASIC and came to the conclusion that the best, and most industry-standard method, involves using a Hardware Description Language.

A Hardware Description Language is a bit like "coding hardware" in the sense that the "code" describes how the circuit is connected.

In other words, you are not writing a program that is read, decoded, and executed by a CPU; you are creating (or, rather, "describing") the physical circuit itself, including every logic gate and bus.

Here is a snippet of code from `ticker.v`:

```
module ticker#(
    parameter COUNT_MAX = 200000
) (
    input wire clk,
    input wire rst_n,
    output wire tick
);

    reg [17:0] count;

    assign tick = (count >= COUNT_MAX) ? 1 : 0;

    always @(posedge clk) begin
        if (~rst_n) begin
            count <= 0;
        end else if (count >= COUNT_MAX) begin
            count <= 0;
        end else begin
            count <= count + 1;
        end
    end

endmodule

```

An 18-bit register which functions like a counter is created, counting all the way to `COUNT_MAX`.

It resembles "normal" code, especially with its C-like syntax, but underneath the surface, is is actually describing a circuit itself, where `tick` is really a wire that toggles between `0` and `1`.

Unlike traditional code, which is sequential, HDL code "runs" in parallel, because it describes an entire circuit at once.

### Resources

I did have some prior knowledge of Verilog and other HDLs, but that was largely from my previous fascination by FPGAs and the [Analogue Pocket](https://analogue.co). I never actually got around to learning it until now.

Learning Verilog from scratch wasn't actually all that bad. In fact, it only took me a week to get comfortable with it.

There were two main resources I used:

- [**_HDLBits_**: a fantastic collection of circuit design exercises for practicing digital hardware design using Verilog](https://hdlbits.01xz.net/wiki/Main_Page)
- [**_ChipVerify_**: a great online library of educational content related to RTL design, digital circuits, and HDLs](https://chipverify.com/)

Apart from that, I also looked at Verilog code other people had written and published on GitHub to get a better sense of the practical architecture and design practices.

## Pong

Time for the fun part: the actual project idea!

I chose to make Pong because it is a project that I have created many times on various different platforms: desktop, web, Arduboy, and even [Pocketbyte](https://pocketbyte.co)!

<img src="/images/MoonPongGameplay.png"></img>

From this experience, I have learned a lot about designing clean architecture, especially in regards to Pong, which has many repeated elements. For example, leveraging tables in Lua for modular logic, or a double-buffering engine on embedded systems.

Rather than designing something completely from scratch for my ASIC, I wanted to implement something I already knew how to do in software and see how the RTL design differences stack up.

So, I decided to make Pong!

How hard could it be?
